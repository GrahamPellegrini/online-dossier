Pipeline Modules

Each node has a narrow responsibility. The audit question is whether the handoff between nodes is reliable enough for replay.

  1. 1

    Quest capture

    Records RGB, depth, headset pose and hand pose for task and orbit sessions.

  2. 2

    Ingestion and MinIO

    Accepts uploads, stores raw inputs and exposes session artifacts for worker processing.

  3. 3

    Hands23 hand detection

    Provides hand/object contact evidence and candidate boxes before object processing begins.

  4. 4

    SAM2 segmentation

    Turns candidate evidence into masks for orbit reconstruction and task-frame object tracking.

  5. 5a

    PointCloudPCA

    Provides model-free task pose estimates when a trusted mesh is not available.

  6. 5b

    FoundationPose with mesh

    Runs when a suitable mesh, mask and depth are available; this is the stronger route for mesh-backed replay.

  7. 6

    Qwen labels

    Supplies an object label from the crop; useful, but still dependent on mask quality.

  8. 7

    DINOv2 and SigLIP

    Support visual identity checks. The current audit keeps DINOv2 and SigLIP rather than adopting DINOv3.

  9. 8

    COLMAP mesh reconstruction

    Reconstructs object meshes from orbit capture frames for canonical mesh-backed replay.

  10. 9

    Headset replay

    Consumes stored objects, tracks, meshes and masks so captured objects can be inspected in VR.

System Status

All status items are shown together. The coloured badge carries the state; open a card for the full note.

Orbit capture route end-to-endHands23 → SAM2 → FoundationPose with mesh, full replay in headset.Modules 3 → 4 → 5b → 9 → statusConfirmed

Verified against ep062, ep064, ep066, ep067. Mesh visible in headset replay. All four sessions return non-null mesh_uri from the live API. Orbit is the trusted capture route for demo.

FoundationPose (pose estimation with mesh)Previously non-functional due to CUDA incompatibility and missing Docker configuration. Now properly containerised and running.Module 5b → statusConfirmed

FoundationPose was originally implemented but could not run because CUDA dependencies were not resolved in the Docker environment. After resolving the container setup, it now provides accurate 6DoF pose estimates for meshed objects. This is the preferred pose estimator when a mesh is available.

SAM2 segmentation (replacing SAM2+SAM3)Object segmentation now uses SAM2 exclusively; the previous SAM2/SAM3 dual setup has been simplified.Module 4 → statusConfirmed

The pipeline previously ran both SAM2 and SAM3 in parallel. This has been simplified to SAM2 only. Segmentation quality is sufficient for both orbit and task capture routes. Hands23 provides the initial grip/hand detection that seeds SAM2 tracking.

Hands23 hand detectionDetects hand grip events and seeds object tracking; replaced a previous subtraction-based approach.Module 3 → statusConfirmed

Hands23 detects hand pose and grip events from RGB frames. It replaced an earlier subtraction-based method. Hand detections are precomputed and stored before OPE runs; missing precompute now raises a clear error rather than silently producing empty output (a regression fixed in September 2026).

COLMAP mesh reconstruction (orbit route)Reconstructs a 3D mesh from orbit capture frames using photogrammetric reconstruction.Module 8 → statusConfirmed

COLMAP processes the orbit capture frame sequence and produces GLB meshes for ocandle01 and oclock02. Mesh quality is good. Meshes are registered as canonical objects and served to Unity for replay rendering.

Episode naming endpointServer generates structured display names (e.g. clock_00_261003) served by UUID; Unity displays verbatim.Module 2 → statusConfirmed

GET /sessions/{uuid}/metadata returns display_name, metadata_revision, processing state, capture timestamp and grasp result. Three states are distinct: pending, unidentified, and identified. Counter scoped per object+date combination, widening past 99. No folder renaming on device.

Mesh in headset replayObject mesh renders in replay instead of wireframe for confirmed demo sessions.Module 9 → statusFixed for demo

Four demo sessions (ep062, ep064, ep066, ep067) now have manual canonical sightings pointing to oclock02 and ocandle01 meshes. Mesh matching remains disabled globally. ep067 bbox was corrected from recorded dimensions to actual mesh extents so Unity shape guard passes.

PointCloudPCA (task route pose fallback)With mesh matching disabled, task sessions fall back to a per-frame point cloud centroid estimate with no temporal memory.Module 5a → statusPartially fixed

PointCloudPCA has no object model and no memory between frames. Confirmed failures: ep062 (fast clock grip) produced metre-scale jumps peaking at 1.05m from hand; ep059 (Stanley cup on table) had a 0.738m excursion despite no movement. A hand-constraint guard was added: during confirmed grip, estimates >0.5m from the nearest wrist/palm are suppressed. This eliminates the worst outliers but does not fix the fundamental accuracy problem. Task route is not demo-ready without a mesh.

Mesh matching (automatic object identification)Automatically matches a live object crop to a library mesh using SigLIP image embeddings.Module 7 → statusDisabled

Mesh matching is disabled (OPE_MESH_RESOLVE_ENABLED=0). Measured accuracy was 4/11 correct on the historical session set, with correct and incorrect scores completely overlapping — no threshold separates them. Re-enabling it would produce incorrect mesh assignments. Manual per-episode overrides are used for demo sessions instead.

DINOv3 encoder consolidationEvaluated replacing SigLIP + DINOv2 with a single DINOv3 encoder to simplify the pipeline.Module 7 → statusEvaluated, not adopted

Proper evaluation with corrected re-ID crops and restored session data. DINOv3-S and DINOv3-B are both lighter than the current pair (225M combined). Re-ID: DINOv2 passes 3/4 hand-to-hand pairs at 0.82 threshold; DINOv3-S and B pass only 2/4. Dense mesh matching: DINOv3-B foreground variant improves retrieval (10/11 vs 4/11) but still falsely assigns absent objects above the true-match score threshold. Not safe for automatic matching. Licence conditionally permits civilian industrial use.

WiFi offline state (Unity client)The Unity client shows connected and unstable WiFi states but has no fully-offline state.Module 9 → statusNot confirmed

When the headset has no network connection, uploads fail silently. OPE does not run, metadata does not pull, and the user receives no clear indication of why. A third WiFi state — fully offline / no connection — needs to be added to the UI with a distinct icon. This is a design request to the Unity developer; server-side handling is not affected.

Maestro server endpoint (shared proxy)Maestro currently uses the shared Faye IT endpoint rather than its own dedicated server endpoint.Module 2 → statusNot confirmed

A request has been submitted to IT Services for a dedicated Maestro server endpoint. The shared Faye proxy is a temporary arrangement and is not suitable for a production deployment. No response received yet. Until Maestro has its own endpoint, the system depends on shared infrastructure that is not under the project control.
