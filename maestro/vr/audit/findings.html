Pipeline Modules

Each node has a narrow responsibility. The audit question is whether the handoff between nodes is reliable enough for replay.

Quest capture

Records RGB, depth, headset pose and hand pose for task and orbit sessions.

Ingestion and MinIO

Accepts uploads, stores raw inputs and exposes session artifacts for worker processing.

OPE worker

Coordinates hand precompute, object evidence, masks, labelling, tracking and publication.

Hands23

Provides hand/object contact evidence and candidate boxes before object processing begins.

SAM2 masks

Turns candidate evidence into masks for orbit reconstruction and task-frame object tracking.

Qwen labels

Supplies an object label from the crop; useful, but still dependent on mask quality.

DINOv2 and SigLIP

Support visual identity checks. The current audit keeps DINOv2 and SigLIP rather than adopting DINOv3.

PointCloudPCA

Provides model-free task pose estimates when a trusted mesh is not available.

FoundationPose with mesh

Runs when a suitable mesh, mask and depth are available; this is the stronger route for mesh-backed replay.

Headset replay

Consumes stored objects, tracks, meshes and masks so captured objects can be inspected in VR.

System Status

The collapsed view is deliberately short for presentation. Open a card to see how the status was confirmed or what remains uncertain.

Confirmed and Working

Orbit route end to endConfirmedHands23 to SAM2 to FoundationPose with a mesh is working for demo-grade orbit captures.

Confirmed through the completed grip-first orbit work, including two metric mesh successes and the documented OOM retry path. This confirms the route for selected captures, not universal reconstruction.

Episode naming endpointConfirmedThe ingestion naming path is in place for readable session identifiers.

Confirmed by the session naming and metadata code/tests present in the project tree; keep it as a usability improvement rather than a perception claim.

Mesh visible in headset replayConfirmedDemo meshes are visible through headset replay for the selected sessions.

Verified against ep062, ep064, ep066 and ep067, with ep067 additionally checked through the live API after its stored bbox correction.

PointCloudPCA hand constraint guardConfirmedImpossible task poses during confirmed grip are rejected when they are more than 0.5m from hand landmarks.

Confirmed by targeted pose-estimator and pipeline tests covering good, boundary, outlier, missing-landmark, world-transform and task/orbit call paths; the worker was restarted after deployment.

Not Yet Confirmed

Task route with reliable poseNot confirmedPointCloudPCA without a mesh still needs stronger end-to-end validation.

The slow candle session is clean, but fast clock motion produced a 1.053m jump and table-contact Stanley produced a 0.738m excursion. The guard blocks one failure mode, not all pose error.

Mesh matchingDisabledAutomatic mesh matching is not accurate enough to trust.

The measured matching baseline remains weak, including a 4/11 result in the historical subset. Corrected DINOv3 experiments improved some foreground retrieval but still made false assignments to absent objects.

DINOv3 consolidationEvaluated, not adoptedThe evaluation is complete, but production should keep DINOv2 and SigLIP.

Real hand-to-hand re-ID passed 3/4 for DINOv2 versus 2/4 for DINOv3 S and B at the current threshold. DINOv3 is lighter, but not better enough to deploy.

Known Issues and Fixes

PointCloudPCA metre-scale jumpsPartially fixedFast grip and contact-heavy motion can still expose task-pose instability.

Slow sessions are clean, and the hand-distance guard now rejects estimates beyond 0.5m from available wrist/palm landmarks during confirmed grip. Further physical constraints are still needed.

ep067 bbox mismatchFixedThe stored bounding box did not match the served clock mesh dimensions.

Corrected from (0.1548, 0.1714, 0.111)m to the served mesh extents (0.22261, 0.11664, 0.08314)m and bumped the session metadata revision.

Wireframe fallback without meshFixed for demo sessionsReplay without a trusted mesh can fall back to a less useful wireframe path.

For the demo sessions, manual canonical sightings and known mesh references are used so the intended mesh appears in headset replay.
